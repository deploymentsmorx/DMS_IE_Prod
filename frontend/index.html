How to use SmorX.ai DMS

Document Management System: connect sources, search files, chat with documents, manage versions, and run governance. Use the left modules in the order below when you are new.

One rule: connect a data source before you expect search or AI answers. Empty Sources means empty results.

Modules (left sidebar)

Document Search Engine

Find files across connected sources.

Use department / type / language filters. Open a result to preview. Use Quick Find for common topics (Inspection, CAD, Invoices).

Document Version

Track revisions of the same document.

Compare versions, keep history, and open the latest approved revision for engineering / quality packs.

Feature Analytics

See usage and search health.

Review volumes, top matches, and whether AI is enabled. Use this when search quality or coverage looks wrong.

Enterprise Governance

Policies, retention, workflows.

Define who can approve, how long files are kept, and governance checklists for controlled documents.

Enterprise Suite

Classification, connectors, AI tools.

Open the embedded suite for deeper enterprise features (classification, AI assistant on the suite side, connector status).

Login & system details

Super Admin only — EXE customer provisioning.

Same Autoballoon-style form: company, license, install password, Device ID, Host name, engineer email, temporary password. Customer Activates, then signs in on the approved PC only. Built-in superadmin is not device-bound.

Customer EXE handoff (Super Admin)

  1. A. Customer opens Activate Login → Activate Customer sends Device ID and Host name from the Activate tab to Super Admin.
  2. B. Super Admin provisions Administration → Login & system details Create organisation + license + device + engineer in one form. Copy License key, Install password, Email, and Temporary password to the customer.
  3. C. Customer Activates then signs in Activate → Sign in Username/password alone is not enough for a customer EXE: they must Activate first. With require-device on, login fails on a different Device ID.

Day-one flow

  1. 1. Sign in Login screen Platform Super Admin: superadmin (not device-bound). Customer engineers: Activate first, then email + temporary password on the approved PC.
  2. 2. Connect a source Data Sources Click Connect a source. Add Local folders and/or OneDrive. Wait for sync; Sources count should rise above zero.
  3. 3. Search Document Search Engine Type keywords or use chips (Department / Type). Open a document from the list. Use Sync in the top bar after new files arrive.
  4. 4. Ask the AI assistant Right panel Ask in plain language about connected files. Answers use document text; select files when you want a scoped reply. Replies are plain bullets.
  5. 5. Versions & governance Modules Use Document Version for revision history. Use Enterprise Governance for retention and approval rules before releasing controlled docs.
  6. 6. Admin (Super Admin) Administration Provision EXE customers with license + install password + device lock. Prefer Admin/User roles for daily engineers; keep platform Super Admin limited.

What good usage looks like

  • Every team member has their own login (not a shared superadmin session).
  • At least one source stays connected; Sync runs after large file drops.
  • Search answers come from real files; AI is used to summarize, not invent.
  • Controlled documents go through Version + Governance before customer release.
